## 五、预警管理接口 NullPointerException 修复

### 现象
预警管理页报错，后端日志：

```
java.lang.NullPointerException: Cannot invoke "Object.hashCode()" because "pk" is null
    at java.base/java.util.ImmutableCollections$MapN.probe(...)
    at ...DisasterEvalController.stats(DisasterEvalController.java:228)
    at ...DisasterEvalController.events(DisasterEvalController.java:116)
```

### 根因
`TYPE_COL` 由 `Map.of(...)` 构建，是 JDK 的**不可变 Map**。不可变 Map 不允许 null 键 —— 即便调 `getOrDefault(null, ...)` 也会在 `probe()` 抛 NPE（不像 `HashMap` 会安静返回默认值）。

预警管理页请求 `/stats`、`/events` 时**不带** `type` 参数 → `@RequestParam(required=false) String type` 为 `null` → `TYPE_COL.getOrDefault(null, ...)` 直接崩。

### 修复
在 `DisasterEvalController` 新增 null 安全辅助方法，`events()` 与 `stats()` 均改用：

```java
private static String levelCol(String type) {
    if (type == null) return "comp_level";
    return TYPE_COL.getOrDefault(type, "comp_level");
}
```

`type` 为空或未知都干净回退到 `comp_level`。

## 七、监测大屏：静态历史概览 → 本年累计态势（随进度条变化）

> 背景：大屏顶部「2020–2023 历史概览」大卡是全年静态聚合（`apiEvalSummary`），与「历史灾害分析→统计概览」重合。
> 用户要求：改为随回放进度条**逐日累积**、跟随时间变化，并注意性能。

### 改动（`views/dashboard/AuroraDashboard.vue`，纯前端）

- 卡片语义：静态全年聚合 → **本年截至回放日的累计态势**，标题实时显示 `截至 {virtualDate}` / 已回放天数 / 进度百分比。
- 三个累计 KPI：累计风险站次 / 累计橙红高风险 / 累计红色站次。
- 两图：累计灾种占比饼图 + **逐日累计风险站次折线**（随回放上扬）。
- Top8 榜单改为"已回放高风险日"；年份切换时累计归零重累；分析页链接修正为 `/disasters`。

### 性能设计

1. **零额外请求**：移除 `apiEvalSummary`，数据完全复用大屏已在推送的当日事件（`useDisasterSocket`），在 `recordDay` 就地累积。
2. **幂等累积**：`date → 桶` 对象存储，同日重复推送（拖拽/跳转/回退触发）覆盖而非叠加，来回拖进度条计数不翻倍。
3. **computed 缓存**：累计量/榜单为 `cumulative` computed，仅在桶变化时重算（桶数 ≤366 个小对象）。
4. **复用 ECharts 实例**：`setOption` 增量更新，不重建图表。
