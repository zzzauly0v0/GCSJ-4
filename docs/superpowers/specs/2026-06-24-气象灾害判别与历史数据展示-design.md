# 气象灾害判别与历史数据展示 — 设计文档

> 日期：2026-06-24
> 状态：已确认，待生成实施计划

## 1. 背景与目标

将 Python 爬取的四川气象站点 2020–2023 逐日观测数据持久化到数据库，后端依据
[`data/算法 .md`](../../算法%20.md) 对每个站点逐日判别四类气象地质灾害（降雨滑坡 / 降雨泥石流 /
冻融滑坡 / 坡面崩塌）并分级，结果写入独立的灾害判别表；前端新增导航页展示 2020–2023
历史气象与灾害分析，并在现有监测大屏加一个入口卡片。

**两个数据表：**
- 数据表：`biz.biz_weather_daily`（已存在，逐日气象观测）
- 灾害表：`biz.biz_disaster_eval`（新建，逐日逐站灾害判别结果）

**关键约束：完全独立。** 灾害判别结果只进新表，不写入现有 `biz_disaster_event` /
`biz_alert`（这两张表已被监测大屏、灾害事件管理、预警发布消费，含 15 条人工演示数据，
不能被算法结果污染）。

### 2.2 灾害判别表（新建）

新文件 `data/05_disaster_eval_schema.sql`，粒度为 **站点 × 日期 一行**：

```sql
SET search_path TO biz, gis, public, postgis;

DROP TABLE IF EXISTS biz.biz_disaster_eval CASCADE;

CREATE TABLE biz.biz_disaster_eval (
    id                 BIGSERIAL PRIMARY KEY,
    station_code       VARCHAR(32) NOT NULL,         -- 关联 biz_monitor_station.code / biz_weather_daily.station_code
    obs_date           DATE        NOT NULL,
    r_eff              NUMERIC(7,2),                 -- 前期有效降雨量 (15日衰减累加 α=0.85)
    dtr                NUMERIC(5,2),                 -- 气温日较差 Tmax - Tmin
    landslide_level    SMALLINT NOT NULL DEFAULT 0,  -- 降雨滑坡   0无 1蓝 2黄 3橙 4红
    mudslide_level     SMALLINT NOT NULL DEFAULT 0,  -- 降雨泥石流 0..4
    freezethaw_level   SMALLINT NOT NULL DEFAULT 0,  -- 冻融滑坡   0..4
    collapse_level     SMALLINT NOT NULL DEFAULT 0,  -- 坡面崩塌   0..4
    comp_level         SMALLINT NOT NULL DEFAULT 0,  -- 综合等级 = 4类取最高 (算法§六)
    comp_index         NUMERIC(4,3),                 -- 综合风险指数 H (算法§五 AHP 加权)
    UNIQUE (station_code, obs_date)                  -- 幂等: 重复跑只更新
);
CREATE INDEX idx_deval_date    ON biz.biz_disaster_eval(obs_date);
CREATE INDEX idx_deval_station ON biz.biz_disaster_eval(station_code);
CREATE INDEX idx_deval_comp    ON biz.biz_disaster_eval(comp_level);
COMMENT ON TABLE biz.biz_disaster_eval IS '逐日逐站气象地质灾害判别结果 (算法 .md, 2020-2023)';
```

入库顺序追加：`04_weather_daily_schema.sql` → `05_disaster_eval_schema.sql`（建空表）
→ `load_weather_stations.py` → 后端 `POST /api/disaster-eval/run`（回填判别结果）。

## 3. 后端 — 算法引擎 + 只读 API

沿用现有 [`ReplayController`](../../../backend/src/main/java/com/gcsj/disaster/controller/ReplayController.java)
确立的 **`JdbcTemplate` 直查、分析型查询** 模式（不引入 entity/service/repository 三件套），
新增两个文件，置于 `controller/` 与同包下的引擎类。

### 3.1 `DisasterEvalEngine.java`（纯算法，可单测）

无 Spring 依赖的纯逻辑类（普通 `@Component` 或静态工具类），实现 [`算法 .md`](../../算法%20.md)：

- **R_eff 前期有效降雨量**（§2.2）：`R_eff = Σ(i=1..15) α^i · R_{t-i}`，α=0.85。
  按站点时间序列滑动计算，缺测日降雨按 0 处理（需在文档注明此约定）。
- **§4.1 降雨滑坡**：按当日降雨 R、R_eff 各自分级取最高；RH≥85% 升一级、RH<60% 降一级。
- **§4.2 降雨泥石流**：R、R_eff 分级取最高；极大风速 V≥10 +1 级、V≥15 +2 级。
- **§4.3 冻融滑坡**：仅当 Tmin<0 且 Tmax>0（发生冻融）才判定；按 DTR 分级；
  叠加 R≥10 或 R_eff≥40 升一级。否则等级 0。
- **§4.4 坡面崩塌**：按 RH 分级；R≥25 时 +1 级。
- **综合**：`comp_level` = 四类取最高（§6）；`comp_index` H = §5 加权
  （w1·f(R)+w2·f(R_eff)+w3·f(RH)+w4·f(V)+w5·f(DTR)，权重 0.35/0.30/0.15/0.10/0.10），
  其中 f(·) 为各因子归一化映射（按 §5.3 H 分级阈值 0.2/0.4/0.6/0.8 反推的分段归一，
  实施时在引擎内以辅助函数明确定义并加注释）。
- 等级裁剪到 [0,4]。

**输入**：某站点按日期升序的逐日记录列表（R/Tmax/Tmin/RH/V）。
**输出**：每日一条判别结果（r_eff, dtr, 4 类等级, comp_level, comp_index）。

### 3.2 `DisasterEvalController.java`（`/api/disaster-eval`）

| 方法 | 端点 | 说明 |
|---|---|---|
| `POST` | `/run` | **手动触发批算**（管理员）。读全部 `biz_weather_daily` 按 station_code+obs_date 升序，逐站调用引擎，`execute`/批量 upsert 进 `biz_disaster_eval`（`ON CONFLICT (station_code,obs_date) DO UPDATE`）。幂等。返回处理站点数与写入行数。可选 `?year=` / `?stationCode=` 限定范围（增量重算）。 |
| `GET` | `/series` | 单站逐日气象+风险时序：`?stationCode=&from=&to=`。JOIN weather_daily + disaster_eval，供 ECharts 折线。 |
| `GET` | `/stations` | 站点列表 + 经纬度 + year_coverage + record_count + 该站历史最高 comp_level，供地图打点染色。 |
| `GET` | `/events` | 风险日列表（comp_level ≥ 1）：`?year=&level=&type=&page=&size=`，按日期倒序分页，供新页面事件表。`type` 映射到具体灾种列。 |
| `GET` | `/heatmap` | 区县级聚合：`?year=&metric=`（rainfall 累计 / 平均 comp_level），JOIN region_code → adcode，供专题热力。 |

权限：`/run` 需管理员；只读接口复用 `dashboard:view`（避免新增 RBAC 种子）。
后端不引入定时任务，不启动自动算。

### 3.3 测试

`DisasterEvalEngine` 用 JUnit 针对 §4 各阈值边界值做单测（如 R=14.9/15/29.9/30…，
冻融 Tmin/Tmax 边界，RH 升降级，风速 +1/+2）。控制器层不强制单测。

## 6. 错误处理与边界

- **缺测值**：CSV 已在入库脚本将 `999999` 等哨兵转 NULL。引擎中 NULL 降雨按 0 参与
  R_eff，NULL 的 Tmax/Tmin/RH/V 使对应灾种判定为 0（无法判别即无风险），需在引擎注释说明。
- **R_eff 跨年/数据缺口**：滑动窗口只在同一站点序列内回看，遇日期不连续按缺测=0 处理。
- **幂等**：`/run` 与入库脚本均用 `ON CONFLICT DO UPDATE`，可重复执行。
- **空数据**：`biz_weather_daily` 为空时 `/run` 返回 0 行而非报错。

## 7. 范围边界（YAGNI）

- 不做实时定时重算（历史静态数据无意义）。
- 不写入 `biz_disaster_event` / `biz_alert`，不派生预警。
- 不改地震移除相关内容（属另一方案文档，本设计不涉及）。
- 大屏只加入口，不做历史数据全量可视化重建。
