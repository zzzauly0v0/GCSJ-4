# AI 灾害助手页面 — 设计文档

- 日期: 2026-07-02
- 状态: 已评审, 待实现
- 相关: 删除空的 `/agent` 路由占位, 重建为真正的「AI 灾害助手」页面; Python AI 后端位于 `spatial_analyse/`

## 目标

在系统中加入一个「AI 灾害助手」页面: 用户用自然语言描述**想去的地点和时间**(如「我 9 月想去九寨沟玩,安全吗?」), Agent 综合**地理定位 → 就近气象站历史灾害数据 → 灾害科普知识**, 产出一段面向游客的**针对性出行风险研判**(该地历史上什么季节、什么灾害高发, 出行建议), 而非干巴巴的通用科普。

不只服务于「游玩」场景, 也可回答其他出行/风险咨询, 但核心能力是**结合站点历史灾害的针对性研判**。

## 整体架构

```
用户: "我9月想去九寨沟玩,安全吗?"
        │  POST /ai/chat (SSE 流式), Vite proxy → :8000
        ▼
Python FastAPI (spatial_analyse/api_server.py)
        │
   Agent Planner (openai-agents SDK, Qwen/DashScope)
        │  自动规划调用哪些 @function_tool
   ┌────┴──────────┬─────────────┐
geo_locate      query_station    disaster_kb
"九寨沟"→经纬度   _disasters       (静态知识库)
                 →就近站历史灾害    →滑坡/泥石流科普
                 (按月份分布)
        │
   Risk Analyzer (LLM 流式)
   "九寨沟一带历史上7-9月泥石流/滑坡风险偏高,
    2022年9月该区域曾达红色级...出行建议: ..."
```

### 关键决策 (已确认)

- **服务架构**: Python 起独立 FastAPI 服务 (`:8000`), 前端经 Vite proxy `/ai` 直连, 与 Java 后端 (`:8085`) 解耦。
- **Agent 框架**: OpenAI Agents SDK 的 `@function_tool` 装饰器, Agent 自动规划工具调用顺序。
- **知识库**: 先用静态知识文档 (Markdown/常量), 不做向量检索; 后续可升级为 RAG。
- **交互体验**: SSE 流式逐字输出 + 多轮对话。

## 第 1 节: 后端服务结构 (spatial_analyse)

现有 `agent.py` 的一次性 stub 由真正的 Agent 逻辑取代。新增文件:

```
spatial_analyse/
  api_server.py       # FastAPI 应用: POST /ai/chat (SSE 流式), GET /ai/health
  agent_core.py       # 定义 Agent + 3 个 @function_tool, 编排规划 + 系统提示词
  tools/
    geo.py            # geo_locate(place) -> 经纬度 (geopy, 已有依赖)
    gis_query.py      # query_station_disasters(...) -> 查 biz_disaster_eval 历史灾害
    knowledge.py      # disaster_kb(topic) -> 返回静态灾害科普/防范知识
  knowledge/
    *.md              # 暴雨/滑坡/泥石流/冻融/崩塌 的科普 + 防范知识 (静态)
```

### 三个工具 (@function_tool)

- **`geo_locate(place)`**: 地名 → 经纬度。用已有依赖 `geopy`。定位失败返回「未找到」, 由 Agent 引导用户换说法。
- **`query_station_disasters(lon, lat)`**: 复用现有 `DB_DSN`, 按经纬度就近找站 (`gis.gis_weather_station`), 统计该站 `biz.biz_disaster_eval` 历史灾害。**除等级/主导灾种统计外, 额外返回按月份分布**, 以回答带时间的问题 (如 9 月为汛期高发)。
- **`disaster_kb(topic)`**: 返回静态灾害科普 + 通用防范知识。

三个工具都用 `@function_tool` 装饰, Agent 自动决定调用顺序 (对应架构图的 Planner)。

### Agent 系统提示词

明确任务: 综合「地理位置 → 就近站点历史灾害 (含月份分布) → 科普知识」, 产出**面向游客的针对性出行风险研判** (该地历史上什么季节、什么灾害高发, 出行建议), 而非通用科普。定位为「出行风险研判助手」。

`pyproject.toml` 新增: `fastapi`、`uvicorn`、`openai-agents`。

## 第 3 节: 数据流、错误处理、验证

### SSE 事件协议 (Python → 前端, 统一 `data:` 帧)

| event 类型 | 载荷 | 前端处理 |
|-----------|------|---------|
| `tool` | `{name, status}` 如 `{"name":"query_station_disasters","status":"正在查历史灾害"}` | 显示「🔧 正在查历史灾害…」占位 |
| `token` | `{text}` 逐字增量 | 追加到当前 assistant 消息 |
| `done` | `{}` | 结束流, 清工具占位 |
| `error` | `{message}` | 消息气泡标红显示错误 |

### 错误处理

- **Python 端**: DashScope Key 缺失 / DB 连不上 / 地名定位失败 → 各自 `error` 帧, 不让整个流崩。地名找不到时 Agent 用工具返回的「未找到」提示引导用户换说法。
- **前端**: `fetch` 流中断 / 后端 500 → 当前气泡显示「AI 服务暂不可用」, 不阻塞页面, 可重发。
- Python 服务没启动时, 前端 `/ai` proxy 502 → 同样降级为友好提示。

### 多轮上下文管理

前端持有完整 `messages`, 每次 POST 全量历史; Python 端无状态 (不存会话), 重启不丢 (历史在前端)。

### 验证方式

1. Python 侧: 起服务后 `curl` 打 `/ai/chat` 看 SSE 帧是否按 `tool→token→done` 顺序返回。
2. 用「我9月想去九寨沟玩安全吗」端到端跑通: 确认三个工具都被调用、返回带月份维度的历史灾害、最终生成出行研判。
3. 前端: 菜单点进「AI灾害助手」, 发消息看流式逐字 + 工具状态提示。
4. 回归: 确认删除空 `agentView.vue`、修 router 后, 菜单渲染不再因 `icon:'Agent'` 报错。
