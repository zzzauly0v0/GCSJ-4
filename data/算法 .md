# 灾害判别批算模块说明

## 1. 模块简介

灾害判别批算模块用于对气象观测数据进行自动灾害识别与风险等级评估。

程序从 `gis.gis_weather_daily` 表读取逐日气象观测数据，按照站点逐个进行灾害判别，并将结果写入 `biz.biz_disaster_eval` 表。

程序支持重复执行（幂等），采用 PostgreSQL `UPSERT` 方式更新已有数据。

---

# 2. 功能流程

整体流程如下：

```text
gis.gis_weather_daily
        │
        │ 读取逐日观测
        ▼
按 station_code 分组
        │
        ▼
逐站灾害判别
        │
        ├── 暴雨
        ├── 高温热浪
        ├── 寒潮
        ├── 干旱
        └── 森林火险
        │
        ▼
计算综合风险等级
        │
        ▼
UPSERT
        │
        ▼
biz.biz_disaster_eval
```

程序执行共分为三个阶段：

1. 读取数据库数据；
2. 逐站进行灾害判别；
3. 写入灾害评估结果。

---

# 3. 输入数据

数据来源：

```text
gis.gis_weather_daily
```

主要字段如下：

| 字段           | 类型      | 说明        |
| ------------ | ------- | --------- |
| station_code | varchar | 站点编号      |
| obs_date     | date    | 观测日期      |
| rainfall     | numeric | 日降水量（mm）  |
| temp_max     | numeric | 日最高气温（℃）  |
| temp_min     | numeric | 日最低气温（℃）  |
| rh_avg       | numeric | 平均相对湿度（%） |
| wind_max     | numeric | 最大风速（m/s） |

程序按照

```sql
ORDER BY station_code, obs_date
```

读取数据，保证时间序列连续。

---

# 4. 输出数据

结果写入：

```text
biz.biz_disaster_eval
```

字段如下：

| 字段              | 说明     |
| --------------- | ------ |
| station_code    | 站号     |
| obs_date        | 日期     |
| rainstorm_level | 暴雨等级   |
| heatwave_level  | 高温热浪等级 |
| coldwave_level  | 寒潮等级   |
| drought_level   | 干旱等级   |
| fire_risk_level | 森林火险等级 |
| comp_level      | 综合等级   |
| comp_index      | 综合指数   |

其中：

```
0 = 无风险
1 = 蓝色
2 = 黄色
3 = 橙色
4 = 红色
```

综合指数计算方式：

```text
comp_index = comp_level / 4
```

保留三位小数。

# 5. 灾害判别算法

## 5.1 暴雨判别

依据：

> GB/T 28592-2012《降水量等级》

根据日降水量划分等级：

| 日降水量(mm) | 等级 | 颜色 |
| -------- | -- | -- |
| <25      | 0  | 无  |
| 25～50    | 1  | 蓝色 |
| 50～100   | 2  | 黄色 |
| 100～250  | 3  | 橙色 |
| ≥250     | 4  | 红色 |

程序直接依据 `rainfall` 字段判断。

---

## 5.2 高温热浪判别

依据：

> GB/T 20481-2017《高温热浪等级》

根据最高气温判定：

| Tmax(℃) | 等级 |
| ------- | -- |
| <33     | 0  |
| 33～35   | 1  |
| 35～37   | 2  |
| 37～40   | 3  |
| ≥40     | 4  |

使用字段：

```
temp_max
```

---

## 5.3 寒潮判别

依据：

> GB/T 21987-2017《寒潮等级》

利用连续两天最低气温变化计算：

```
降温 = 前一天最低气温 − 当天最低气温
```

等级如下：

| 24h降温(℃) | 等级 |
| -------- | -- |
| <6       | 0  |
| 6～8      | 1  |
| 8～10     | 2  |
| 10～12    | 3  |
| ≥12      | 4  |

使用字段：

```
temp_min
```

程序需要连续日期，因此每个站点按日期排序。

---

## 5.4 干旱判别

依据：

> GB/T 20481-2017《气象干旱等级》

由于仅有单年观测数据，无法计算多年降水距平，因此采用月累计降水简化方案。

程序首先统计：

* 月累计降水
* 月总天数
* 无雨日比例

其中：

```
无雨日：

rainfall < 0.1 mm
```

随后按照干季、湿季分别采用不同阈值。

### 干季（11～4月）

| 月降水(mm)     | 等级 |
| ----------- | -- |
| <30         | 1  |
| <20         | 2  |
| <10         | 3  |
| <5 且无雨日>90% | 4  |

### 湿季（5～10月）

| 月降水(mm) | 等级 |
| ------- | -- |
| <80     | 1  |
| <60     | 2  |
| <40     | 3  |
| <20     | 4  |

同一个月内所有日期采用相同干旱等级。

---

## 5.5 森林火险判别

依据：

* LY/T 1172-95
* QX/T 77-2007

综合：

* 最高气温
* 平均湿度
* 最大风速

进行判别。

| 条件                          | 等级 |
| --------------------------- | -- |
| Tmax≥20 且 RH≤45 且 Wind≥3.3  | 1  |
| Tmax≥25 且 RH≤35 且 Wind≥5.5  | 2  |
| Tmax≥28 且 RH≤25 且 Wind≥8.0  | 3  |
| Tmax≥30 且 RH≤15 且 Wind≥10.8 | 4  |

涉及字段：

```
temp_max
rh_avg
wind_max
```

---

# 6. 综合风险评价

程序对五类灾害进行统一评估。

```
综合等级 = max(
    暴雨,
    高温,
    寒潮,
    干旱,
    森林火险
)
```

即：

任何一种灾害达到较高等级，则综合等级采用最高值。

综合指数：

```
comp_index = comp_level / 4
```

例如：

| 综合等级 | 综合指数  |
| ---- | ----- |
| 0    | 0.000 |
| 1    | 0.250 |
| 2    | 0.500 |
| 3    | 0.750 |
| 4    | 1.000 |

---

# 7. 数据写入策略

采用 PostgreSQL：

```sql
INSERT ...
ON CONFLICT
DO UPDATE
```

即：

* 数据不存在时插入；
* 已存在时更新。

保证程序重复运行不会产生重复记录，实现幂等更新。

---

# 8. 命令行参数

程序支持以下运行方式：

全部年份：

```bash
python run_disaster_eval.py
```

指定年份：

```bash
python run_disaster_eval.py --years 2020,2021,2023
```

指定站点：

```bash
python run_disaster_eval.py --station 56571
```

也可同时指定：

```bash
python run_disaster_eval.py --years 2023 --station 56571
```

---

# 9. 程序输出

程序运行结束后自动统计：

```text
各年份总记录数
```

例如：

```text
2020 : 36500
2021 : 36500
2022 : 36500
```

随后统计：

```text
comp_level >= 1
```

即风险天气日数量，例如：

```text
风险日：

2020 : 5234
2021 : 5487
2022 : 5103
```

用于验证灾害判别结果是否正确写入数据库。

---

# 10. 模块特点

* 支持五类典型气象灾害自动识别。
* 依据国家及行业标准完成等级划分。
* 采用统一四色预警体系（0～4级）。
* 综合风险采用最高等级原则，便于统一评估。
* 支持按年份或站点批量计算，提高运行效率。
* 使用 PostgreSQL `UPSERT` 实现幂等更新，可重复执行且不会产生重复数据。
